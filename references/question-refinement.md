# 问题打磨方法卡（源自 good-question，Rimagination, MIT License）

把"我想研究 X"炼成"我将检验在 Z 条件下 Y 是否带来可测量的 W"。

## 核心动作（缺一不可）

1. **重要性论证**：为什么这个问题值得投入？对谁重要？回答不了就换题。
2. **竞争性假设**（Platt, 1964, "Strong Inference"）：列出 ≥2 个相互竞争的解释，问题必须能设计出判别实验/证据来区分它们。只有一个解释 = 还不是好问题。
3. **假设挑战**（Alvesson & Sandberg, 2011, problematization）：不要只找文献空白——追问该领域默认假设是否成立。空白填了增量有限，默认假设被撼动才有理论贡献。
4. **Heilmeier Catechism** 自问：要解决什么、为什么现在做、谁关心、风险在哪、成功与失败的判据分别是什么。
5. **可证伪性**：写清"什么结果会推翻我的预期"。写不出推翻条件 = 问题不可检验。

## 综述场景特化（PICO / PCC / SPIDER）

- 定量 → **PICO**：Population, Intervention, Comparison, Outcome
- scoping → **PCC**：Population, Concept, Context
- 定性/混合 → **SPIDER**：Sample, Phenomenon of Interest, Design, Evaluation, Research type
- realist → 问题形式为"什么机制（M）在什么情境（C）下产生什么结果（O）"

## 三项 Litmus Test（借鉴 research-question-refiner）

| 测试 | 通过标准 |
| --- | --- |
| Advisor Test | 2 分钟陈述后，忙碌的导师会说"去做"，而不是"再聊聊" |
| Paper Test | 能预想成稿的标题、摘要核心句和图 1 |
| Null Result Test | 假设被推翻时，综述结果仍然有价值、可报告 |

## 流程

1. 复述用户粗方向 → 小规模试检索（用 search 脚本，每库 ≤30 条）看文献实况
2. 输出 1-3 个候选问题（各附：重要性、竞争假设、证伪条件、建议综述类型）
3. 用户选定后（模式2 由 AI 选定并记录），写入 protocol 的 objectives，锚定后续检索策略
